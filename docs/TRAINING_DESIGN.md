# TRAINING_DESIGN.md — TRAINING の教育設計（v1.3）

## 0. この文書の位置づけ

TRAINING は「答えを覚える場所」ではなく、
**実戦のアレンジ判断を反復して身につける教材**です。

- CHECKOUT: 「どう上がるか」を判断できるようになる
- SETUP: 「最後の 1 投で悪い残りを避け、次のラウンドで上がれる残りへ整える」判断ができるようになる
- RECOVERY: 「外したあとに、残り点と本数から正しく組み直す」判断ができるようになる
- MIXED: この 3 つを実戦のように切り替えられるようになる

**通常 Practice の戦術ロジック（ランキング・基準ルート・重み）は TRAINING のために変更しません。**
TRAINING が持つのは「出題」「採点の概念分離」「feedback」「履歴」だけです。

---

## 1. v1.2 までの問題

SETUP TRAINING は「3 投を合法に投げられたら正解」でした。

全 173 件の SETUP 出題に `S20 → S20 → S20` と答えると、
**173 / 173 がルール上 valid** になります。
しかし、次のラウンドで上がれる残りを作れるのは 53 件だけで、
残り 120 件（69.4%）は Bogey（ノーテン）か 170 超えを残します。

つまり「同じ 20 を打ち続ける」だけで正答率が 100% になり、
**SETUP で最も大事な判断を一度も練習しないまま終われて**しまいました。

## 2. ruleValid と learningCorrect

採点を 2 つの概念に分けます（`src/engine/training/grade.ts`）。

| 概念 | 意味 |
| --- | --- |
| `ruleValid` | ルール上その回答が成立するか（合法か） |
| `learningCorrect` | 学習目的として正解か |

- CHECKOUT / RECOVERY: 合法な Double Out が完成すれば両方 true。
  **C ランクのルートでも、数学的に成立していれば `learningCorrect` は true** です
  （推奨度は別軸として表示します）。
- SETUP: 合法に投げ切れても、残りが Bogey / 170 超えなら
  `ruleValid = true` / `learningCorrect = false`。

**主 UI の正答率は `learningCorrect` で数えます。**
`ruleValidRate` は内部指標として保持します。

## 3. SETUP の Hybrid 出題

| 形式 | 割合 | 10 問 | 30 問 |
| --- | ---: | ---: | ---: |
| 1 投調整（`setup-adjustment`） | 80% | 8 | 24 |
| 1 投目の選択（`setup-first-dart`） | 20% | 2 | 6 |

**v1.3.4 で 3 投フル形式（`setup-full`）の新規出題を停止しました。**
`303 / 3 本` で `T20 → T20 → T20 = 180` → 123 残しのように、
「とりあえず T20 を 3 本」でも正解になる問題が多く、
「なぜ最初から 19 へ振るのか」を学べなかったためです。
型・採点・feedback は**保存済み履歴を読むために残して**あります
（`buildPools()` が返す `setupFull` が常に空になるだけです）。

### 3-1. 1 投調整（主教材）

```
SETUP / 残り 1 投

開始:    226
ここまで: S20 → S20   ← 実際に入った結果（読み取り専用）
現在:    186

次のラウンドで上がれる残りにするには、どこを狙いますか？
```

- 先行 2 投は **ユーザーの回答ではなく「実際に入った結果」** です。
  回答欄には入れず、読み取り専用で表示します。
- 回答は盤面から 1 か所だけ選びます。自動確定はせず「回答する」で採点します。

### 3-3-1. decisionRequired（v1.3.4）

「調整が必要」という教材なのに、**調整しなくても普通にテンパイになる**問題まで
出していました。たとえば `284 / T18 → T18 / 現在 176` は

```
18 を続ける : T18 → 122 ○ / S18 → 158 ○
20 へ戻る   : T20 → 116 ○ / S20 → 156 ○
```

でどこへ入っても上がれるので、実戦では何も考えずに投げてよい場面です。

v1.3.4 で `decisionRequired` を追加し、v1.3.5 で条件を

> 1. シングル面に入ってもトリプル面に入っても上がれる**ナンバー**が存在する
> 2. しかし自然に狙うナンバー（直前と同じナンバー / 主目標の 20）はどれもそうではない

の 2 つが同時に成り立つ場合だけ、へ変更しました。
言い換えると、**狙うナンバーを変えると結果が変わるときだけ出題する**ということです。

**固定の下限（182 以上など）ではありません。** 計算で決めるので、
179（`S20 → 159` のノーテン）は入り、184 / 187（20 のままで上がれる）は入りません。
Bust する着弾はこの教材が扱う「悪い残り」に含めません（3 節の列挙どおり
Bogey / 170 超え / テンパイ不能だけを見ます）。

v1.3.4 の条件（自然な狙いが safe でなければ出題）では、次のような
「選びようがない」問題まで出ていました。

```
312 / T20 → T20 / 現在 192
  20  : T20 → 132 ○ / S20 → 172 ×（170 超え）
  ほかのどのナンバーも、シングル面は 170 を超える
  → 20 以外を選ぶ理由が無い。T20 で 132 の余裕あるテンパイ

215 / S20 → S1 / 現在 194
  どのシングル面でも上がれない → T20 の一択
```

どちらも v1.3.5 では出題しません。

BULL エリアはナンバーの候補に含めません。「狙って外すと同じナンバーのシングル面」
というモデルが当てはまらないためです（SETUP のシングル落ち判定が BULL を
対象外にしているのと同じ理由）。

この結果、出題されるのは次の **7 つの現在残りだけ**になりました
（1 投調整の候補は 1,318 件 → 58 件）。

| 現在残り | 20 を続けたときのシングル面 |
| ---: | --- |
| 179 | 159（ノーテン） |
| 182 | 162（ノーテン） |
| 183 | 163（ノーテン） |
| 185 | 165（ノーテン） |
| 186 | 166（ノーテン） |
| 188 | 168（ノーテン） |
| 189 | 169（ノーテン） |

Bogey Number + 20 と一致しますが、表で持っているわけではなく、
シングル面に落ちたときの残りから毎回計算しています。

出題範囲を狭くして該当が 1 件も無くなる場合（例: 171〜182 は 2 投投げ終えた時点で
残りが小さく、どこを狙っても上がれる）は、「出題できません」で終わらせず、
これまでどおりの候補へ決定論的に戻します。

### 3-3-1-1. 回答はナンバー（v1.3.5）

SETUP の回答は、盤面 62 セグメントではなく **1〜20 のナンバー**から選びます。
決めるのは「どのナンバーのウェッジへ投げるか」であって、
シングル面とトリプル面のどちらに刺すかではないからです。

入力は、盤面で **1 ナンバーぶんの扇形（シングル・トリプル・ダブルをまとめた
エリア）をタップ**します。数字ボタンを並べると盤面の並び（20 → 1 → 18 → …）と
一致せず、目的のナンバーを探す時間がかかるためです。
BULL は選べません（中心は 20 個のウェッジが 1 点に集まります）。

採点もナンバー単位で行います。

```
現在 182
  20 を選ぶ → T20 なら 122 ○ / S20 なら 162 ×（ノーテン）→ 不正解
  18 を選ぶ → T18 なら 128 ○ / S18 なら 164 ○            → 正解
```

「狙いどおりトリプルに入れば上がれる」だけでは正解にしません。
安全なナンバーが 1 つも無い残り（190 以上など）では、存在しない安全さを要求せず、
これまでどおり「実際に作った残りが上がれるか」で採点します。

### 3-3-2. 1 投目の選択（`setup-first-dart` / v1.3.4）

```
SETUP / FIRST DART

残り 299 点。このラウンドは 3 投あります。
1 投目はどこを狙いますか？
```

学ぶのは「高得点を狙うだけではなく、**シングルへ落ちてもテンパイへの道が残る**
第一ターゲットを選ぶ」ことです（`docs/SETUP_THEORY.md` §10）。

- 回答は **1 投だけ**。このラウンドは 3 投あるので、
  回答後に 170 以下になる必要はありません。
  `gradeSetupAnswer()`（回答後 leave が checkoutable なら正解）は使いません。
- 採点
  - `ruleValid` … 盤面上の合法なターゲットを 1 つ選べている
  - `learningCorrect` … その的が**得点用の開始ターゲット**であり、かつ
    同ナンバーのシングルへ落ちても残り 2 本でテンパイを作れる
- **採点は盤面のすべてのトリプルを規則どおり判定します。**
  「ランキングの上位何件に現れるか」で正解・不正解が変わってはいけません
  （例: 299 の T9 は 272 で狙いどおり、S9 へ落ちても 290 でテンパイを作れるので正解。
  ただし取得点が低いぶん推奨度は下がります）。
  広いシングル（S18 など）を狙えば確かに外しようがありませんが、
  それは得点の組み立てを捨てているので正解にしません。
- **出題する残り点**は「第一ターゲットによって耐性に差が出る残り」だけ（14 件 / 297〜310）。
  ここでは取得点の多い順に上位 3 つ（ふつうは T20 / T19 / T18）だけを見ます。
  盤面のトリプル 20 種すべてを見ると、T1 のような誰も狙わない的が危険というだけで
  教材になってしまうためです。
  どのトリプルから入っても安全な残りを並べても、考えずに T20 と答えて
  正解になってしまい、やはり教材になりません。

| 残り | おすすめ | 危険な的 | 難易度 |
| ---: | --- | --- | --- |
| 297 / 298 | T20 | T18 など | medium |
| **299** | **T19** | T20 | hard |
| 300 / 301 | T20 | T18 / T19 など | medium |
| **302** | **T18** | T20 | hard |
| **303** | **T19** | T20 | hard |
| 304 | T20 | T19 / T18 など | medium |
| **305** | **T18** | T20 | hard |
| **306** | **T19** | T20 | hard |
| 307 | T20 | T19 / T18 など | medium |
| **308** | **T18** | T20 | hard |
| **309** | **T19** | T20 | hard |
| 310 | T20 | T19 / T18 など | medium |

安全な的が複数あるときは、**取得点の多い方**をおすすめにします
（SETUP の「同じ質の残りを作れるなら点を多く取る」と同じ考え方）。
安全な代替も `learningCorrect = true` とし、推奨度 S / A / B で差を付けます。
シングル落ちでテンパイを失う的は、スコアが高くても C とします。

feedback は「シングルへ落ちた場合」を並べて見せます。

```
あなた  : T20 / S20 へ落ちると 279 / 残り 2 本 — このラウンドではテンパイを作れません。
おすすめ: T19 / S19 へ落ちると 280 / 残り 2 本 — T20 → T20 で 160 残しを作れます。
理由    : T20 狙いは S20 へ落ちると残り本数でテンパイ不能ですが、
          19 からなら、シングルへ落ちてもテンパイへの道が残ります。
```

同じ現在残りは、**複数の先行投球 context から出題されます**（各 10 通り）。
たとえば現在 182 は `302 / T20 → T20` だけでなく
`222 / S20 → S20`、`247 / T20 → S5`、`290 / T18 → T18` などからも作られるので、
開始残りの暗記ではなく「182 なら 18」という技術として反復できます。

### 3-4. 推奨以外の正解

推奨解答だけを唯一の正解にはしません。
226 / 186 で `S16 → 170` のように、上がれる残りを作る合法な回答は
すべて `learningCorrect = true` とし、その上で S / A / B / C の二次評価を付けます。

| 記号 | カテゴリ | 内容 |
| --- | --- | --- |
| A | `setup-bogey-avoid` | 一般的なノーテン回避 |
| B | `setup-adjust-18-19-20` | 18 / 19 / 20 へのずらし |
| C | `setup-digits-0147` | 0・1・4・7（159〜170 帯） |
| D | `setup-302-309` | 302〜309 の 3 投目調整 |
| E | `setup-ton-trap` | 「とりあえず TON」の罠 |
| F | `setup-landing-95-105` | 95〜105 への着地 |
| G | `setup-sbull` | S-BULL 25 での調整 |
| H | `setup-same-number-worse` | 同じ数字を続けると悪化する |
| I | `setup-basics` | 基礎確認 |
| J | `setup-first-dart-safety` | 第一ターゲットのシングル落ち耐性（v1.3.4） |

出題の優先順は D > E > F > G > C > H > B > A > I。
カテゴリの判定は「具体的なものから順に 1 つだけ」割り当てます。

J だけが `setup-first-dart` 形式に対応し、カテゴリ quota ではなく
**形式の 20% 枠**から取ります。履歴から「ラスト 1 投の調整が苦手」と
「第一ターゲット選択が苦手」を区別できるようにするための分離です。

### 新規出題されなくなるカテゴリ（v1.3.4 → v1.3.5）

`decisionRequired`（3-3-1）で 1 投調整を絞った結果、次の 4 つは
**候補が 0 件になりました**（型と保存済み履歴はそのまま読めます）。

| カテゴリ | なぜ 0 件になるか |
| --- | --- |
| A `setup-bogey-avoid` | 継続の的が問題ない場合にだけ付くカテゴリなので、`decisionRequired` と両立しない |
| B `setup-adjust-18-19-20` | 同上 |
| I `setup-basics` | 定義そのものが「判断が要らない問題」 |
| H `setup-same-number-worse` | v1.3.5 で出題が 7 つの現在残りへ絞られ、この帯に該当が残らなくなった |

学習内容が消えたわけではありません。「20 を続けるとノーテンになるから 18 へ」という
判断は C `setup-digits-0147` と D `setup-302-309` が受け持ち、
`shift-20-to-18` / `shift-20-to-19` の学習タグは今までどおり付きます。

現在の候補数は次のとおりです（v1.3.5）。

| カテゴリ | 1 投調整の候補数 |
| --- | ---: |
| C `setup-digits-0147` | 31 |
| E `setup-ton-trap` | 11 |
| G `setup-sbull` | 6 |
| D `setup-302-309` | 6 |
| F `setup-landing-95-105` | 4 |
| J `setup-first-dart-safety`（別形式） | 14 |

候補が 4 件しかない F は、30 問セッションで計画どおり 4 枠を埋められない seed が
出ます（7 つの現在残りしか無いため、直近 3 問に同じ状況を出さない制約と
両立しないことがある）。そのときはカテゴリを 1 枠だけ外します。
**形式の 80/20 は崩しません**（`docs/APPROVALS.md` A-15）。

### quota

基準となる quota（`setupCategoryQuota()`）は次のとおりです。J は 0 で、
形式の 20% 枠から取ります。

| | A | B | C | D | E | F | G | H | I | J |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10 問 | 2 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 0 |
| 30 問 | 6 | 4 | 3 | 4 | 4 | 3 | 3 | 2 | 1 | 0 |

実際に配る枠は `plannedSetupCategoryQuota()` が決めます。

1. 20% を `setup-first-dart` へ回す（候補が足りなければ不足分を
   `setup-adjustment` へ戻し、件数を report の `firstDartShortfall` に出す）
2. 残りの枠へ、**出題できるカテゴリだけ**で quota を配り直す

候補が存在しないカテゴリのぶんは、利用可能なカテゴリへ **決定論的に**再配分します
（infinite retry はしません）。再配分した件数は sampler の report に出ます。

**v1.3.4: 余り枠は「候補の多いカテゴリ」から配ります。**
優先度順（D > E > …）で配ると、いちばん具体的で候補の少ない D（6 件）へ枠が集まり、
「直近 5 問に同じ問題を出さない」と両立できなくなるためです。

その結果、30 問 SETUP セッションの内訳は次のように計画されます。

| C | D | E | F | G | H | J |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 4 | 5 | 4 | 4 | 3 | 6 |

復習（`reviewWeakFirst`）を切れば、この計画と実際の出題は完全に一致します。
復習を入れると、出題順の制約（末尾 2 問のどちらかは HARD など）と両立しないとき、
同じ形式のまま別カテゴリへ広がることがあります（1 セッションあたり合計 ±2 まで）。

### 学習タグ

ラスト 1 投の調整には、次のタグが付きます。

| タグ | 意味 |
| --- | --- |
| `last-dart-adjustment` | 残り 1 投の調整問題である |
| `avoid-bogey-on-last-dart` | そのまま 20 を続けるとノーテン / 170 超えになる |
| `shift-20-to-18` / `shift-20-to-19` | 20 から 18 / 19 へずらすのが推奨 |
| `setup-last-dart\|current=182\|target=S18` | **現在残りを主語にした学習単位** |
| `decision-required` | 自然な狙いのままでは悪い残りになりうる（v1.3.4） |

1 投目の選択（`setup-first-dart`）には、次のタグが付きます。

| タグ | 意味 |
| --- | --- |
| `first-dart-safety` | ラウンドの 1 投目を選ぶ問題である |
| `single-miss-tenpai-safe` | シングルへ落ちてもテンパイへの道が残る的がある |
| `avoid-single-miss-dead-end` | シングルへ落ちるとテンパイ不能になる的が混ざっている |
| `setup-first-dart\|start=299\|target=T19` | **その残りからの入り方**という学習単位 |

最後のものが重要です。`problemKey` は問題 instance の識別子（開始残りを含む）ですが、
このタグは context をまたいだ「技術」の識別子なので、
**「302 を間違えた」ではなく「182 からの 3 投目調整が苦手」**と認識できます。
学習履歴のタグ別成績と復習対象（`reviewTargetsOf`）はこのタグを見ます。

## 5. 難易度

### CHECKOUT

```
difficultyPoints = (ルート長 - 1) + トリプル含有 + BULL 含有 + (LEFT >= 100) + (的の切り替え 2 回以上)
EASY 0〜1 / MEDIUM 2〜3 / HARD 4 以上
```

10 問: EASY 2 / MEDIUM 4 / HARD 4（1 投上がりは最大 1）
30 問: EASY 6 / MEDIUM 12 / HARD 12（1 投上がりは最大 3）

### RECOVERY

- EASY: 1 本で上がれる
- MEDIUM: 2 本。BULL もトリプルも必須ではない
- HARD: BULL finish が必須、またはトリプルが必須

10 問: 2 / 5 / 3 、30 問: 6 / 15 / 9

### SETUP

- EASY: 基礎確認（I）。継続の的でもすでに上がれ、ノーテン・170 超えの判断が要らない
- MEDIUM: 18 / 19 / 20 のずらし、Bogey・0/1/4/7 の判断（A / B / C / D / H）と、
  1 投目の選択のうち **主目標の 20 がそのまま安全**なもの（J / medium）
- HARD: TON トラップ、95〜105、S-BULL（E / F / G）と、
  1 投目の選択のうち **20 を捨てて 18 / 19 から入る**もの（J / hard）

目安は 10 問 2 / 5 / 3、30 問 6 / 15 / 9 だが、**SETUP はカテゴリ quota が優先**なので
この目安どおりにはならない。難易度は (カテゴリ, 形式) から一意に決まるため、
実際の分布は「カテゴリ quota が決める決定論的な範囲」になる。

**v1.3.4: EASY は出題されなくなった。** EASY にできるのは基礎確認（I）だけで、
`decisionRequired`（3-3-1）によって I の候補が 0 件になったためです。
実測の分布は MEDIUM 6 / HARD 4（10 問）、MEDIUM 17〜20 / HARD 10〜13（30 問）付近。

**1 投目の選択の難易度は、枠数に比例して先に配ります。**
1 問ずつ「残り枠の多い難易度」を選ぶ配り方だと、SETUP 全体では MEDIUM の枠が多いため
1 投目の枠がすべて MEDIUM になり、教材の核である HARD 側（299・302・303 …）が
1 問も出なくなっていました。

**採点の推奨度は「第一ターゲットの推奨度」で統一します。**
その的から投げ切ったときの 3 投ルートの推奨度をそのまま出すと、
「判定は C なのに回答カードは S」のような食い違いが起きます。

目安へ寄せるにはカテゴリ quota（§4）か難易度の分類そのものを見直す必要があり、
どちらも人間の承認が要る。実装側で目安に合わせて教育カテゴリを崩すことはしない。

### trivial（判断が要らない問題）

「継続の的でもすでに上がれる」だけでは trivial にしない。
**継続の的で上がれ、かつノーテン・170 超えの判断が一切要らない**場合だけを trivial とする
（= 基礎確認カテゴリ）。304 のように「20 を続けても 164 で上がれる」問題も、
166 のようなノーテンを選べる以上は判断が要るので trivial ではない。

出題数の上限は 10 問で 2、30 問で 6。
CHECKOUT の 1 投上がりは 10 問で 1、30 問で 3。

**v1.3.4 以降、SETUP の trivial は 0% になりました。**
`decisionRequired`（3-3-1）で基礎確認カテゴリの候補が無くなったためです。

**カテゴリ quota を優先**し、難易度が完全一致できない場合は
実際の分布を report に出します（`npm run audit:training`）。

## 6. 出題 sampler

`src/engine/training/sampling.ts`。random retry loop は使いません。

1. quota 計算（種別 / カテゴリ / 難易度 / 形式）
2. 各 bucket を seed 付き shuffle（cursor を進めて一巡させる）
3. review bag 生成（復習 bucket は「間違えた問題そのもの」を優先度順に並べる）
4. 直近履歴による除外
5. 候補選択
6. 足りないときだけ決定論的に条件を緩める

### anti-repeat

- 同じ `problemKey` は直近 5 問に出さない
- 同じ状況（現在残り × 使える本数）は直近 3 問に出さない。
  開始残りは含めない — `302 → T20 → T20 → 182` と `222 → S20 → S20 → 182` は、
  残り 1 投の判断としては同じ問題なので、続けて出しても新しい練習にならない
- 直前とまったく同じ問題は、候補が 1 件しかない場合を除いて禁止
- MIXED の同じ種別は最大 2 連続
- HARD は 3 連続させない
- 10 問セッションの 1 問目は EASY か MEDIUM、最後の 2 問のどちらかは HARD

`problemKey` は index を含まない安定キーで、期待解答は含みません。

```
checkout|v2|left=103|darts=3
setup|v2|adjust|start=226|ctx=S20,S20|current=186|darts=1
setup|v2|full|start=265|darts=3
recovery|v2|start=122|intended=T18|actual=S18|current=104|darts=2
```

### 出題順は「並べ替え」で満たす（緩和ではない）

出題順の制約（HARD 3 連続・1 問目・最後の 2 問）は、**選択の前に slot の並びで**満たします。
並べ替えるだけなので、種別ごとの (カテゴリ, 形式, 難易度) の多重集合は変わりません。
MIXED の種別並び・SETUP の 80/20・A〜I のカテゴリ quota は、並べ替えでは崩れません。

1 つずつ交換して違反を減らす貪欲法では足りません。
「交換すると別の違反が生まれるが、2 手先では解ける」並びがあるためです。
たとえば 171〜182 の 10 問では 3 投フル候補 12 件がすべて HARD なので、
その枠が 1 問目に来ると「1 問目は HARD にしない」と衝突し、
1 手の交換ではどれを試しても違反が 1 件のまま残ります。

そこで、難易度の並びを**決定論的な深さ優先探索**で 1 度だけ決め、
その並びへ slot を配り直します。

- 各位置では「計画どおりの難易度 → EASY → MEDIUM → HARD」の固定順で試す
- 失敗した状態（位置・HARD の連続数・残りの多重集合）を記録して打ち切る
- random retry loop は使わない。同じ seed からは常に同じ並びになる

復習枠は難易度 quota ではなく score 順で配るので、**復習枠を決めたあとに並べます**。
復習枠を置く場所も、計画した難易度と一致する slot を先に使います
（HARD の苦手問題が 3 枠に入ると HARD が増えすぎて、並び自体が実現できなくなるため）。

**復習枠の難易度は計画時点では予測でしかありません。** 復習 bucket は score 順で配り、
直近履歴や出題順で弾かれると別の候補へ落ちるためです。
そこで **最後の 2 問の HARD は、難易度が確定している slot（復習枠でない slot）で満たします。**
予測に頼ると、予測が外れたときに最後の 1 問で HARD を作り直すことになり、
その位置のカテゴリに HARD 候補が無ければカテゴリ quota が崩れます
（独立監査 F-010: MIXED 30 問 + 復習で 12 / 3,000 セッション）。

その多重集合では並びが存在しない場合（例: 10 問中 HARD が 7 問）にだけ、
復習枠を後ろから 1 つずつ諦めます。出題順・形式・カテゴリ・難易度の quota は崩しません。

### 優先順位と、条件を緩める順序

守れないものが出たとき、何を先に諦めるかを一列に決めてあります。上が強い。

| | 制約 | 扱い |
| ---: | --- | --- |
| 1 | 数学的・ルール上の正しさ | 絶対 |
| 2 | 形式 quota（SETUP の 80/20） | 絶対（緩めない） |
| 3 | 出題順（HARD 3 連続なし・1 問目・最後の 2 問） | 並べ替えで満たす |
| 4 | trivial / 1 投上がりの上限 | 緩めるのは 3 の次 |
| 5 | anti-repeat（直近 5 問の同じ問題・直近 3 問の同じ状況） | 緩めるのは 4 の次 |
| 6 | カテゴリ quota（A〜I） | 5 より先に譲る |
| 7 | 難易度 quota | 6 より先に譲る |
| 8 | 復習枠 | いちばん先に譲る |

選択ループの入れ子はこの順です。外側ほど後まで守られます。

```
出題順 → trivial / 1 投上がり上限 → 直近履歴の窓 → カテゴリ（bucket）→ 難易度
```

- 直近履歴の窓は 5 問 / 3 問 → 5 / 1 → 5 / 0 → 3 / 0 → 1 / 0
- 難易度は 希望 → **種別の難易度 quota が残っている難易度** → 制約なし
- カテゴリを外した bucket を使ったぶんは、決定論的な quota 正規化として
  report の `quotaNormalizedCount` に出ます

難易度の中間段階（quota 残）が重要です。希望した難易度が出題順の制約で使えないとき、
これが無いと **すでに quota を使い切った難易度を選び直して**しまいます。
RECOVERY の EASY と SETUP の基礎確認は定義上 trivial なので、
EASY が quota を超えると trivial 上限（10 問 2 / 30 問 6）を押し出します。

**形式（SETUP の 80/20）は緩めません。** bucket を広げるときもカテゴリだけを外し、
形式は保ちます。形式を落とした bucket を挟むと、計画した 3 投フルの枠が
「同じカテゴリの 1 投調整」で埋まり、80/20 が崩れます
（独立監査 F-006: 171〜182 の 10 問で 8 / 2 が 9 / 1 になっていた）。

**カテゴリ quota は anti-repeat より先に譲ります。**
狭い出題範囲では、正規化後のカテゴリ枠に候補が 1 件しかないことがあります
（171〜182 の `setup-bogey-avoid` と `setup-same-number-worse` は 1 投調整が各 1 件）。
その 1 件を出し直してカテゴリ quota を見かけ上そろえると、
同じ問題が 10 問中 2 回出ます（独立監査 F-008: 10,000 セッション中 5,051 件）。
1 投調整の候補は範囲全体に 120 件あり候補不足ではないので、
**形式を保ったまま別カテゴリへ決定論的に広げます。**
default の出題範囲ではカテゴリ枠に十分な候補があるので、この正規化は起きません。

**出題順の制約は選択時にも実際の難易度で確認**します。
判定には slot 計画ではなく **実際に選ばれた `question.difficulty`** を使います。
緩めた回数は report に出ます。

復習枠だけは例外で、難易度 quota と trivial 上限を見ません。
「その問題をもう一度出す」ための枠なので、難易度の合う別問題を先に選ぶと目的を果たせません。
直近履歴の除外（5 問 / 3 問）は復習枠でも外しません。

**復習枠は出題構成を崩しません。** 復習に使うのは、計画した形式とカテゴリの
両方に一致する苦手候補がある slot だけです。両立する slot が復習 quota より少ない
場合は復習枠を減らします（苦手を出すために 80/20 や A〜I の quota を崩さない）。

出題範囲が狭く、3 投フルを出せるカテゴリの枠が足りない場合は、
full を出せないカテゴリの枠を決定論的に譲って 80 / 20 を保ちます
（譲った件数は report の `quotaNormalizedCount` に出ます）。

### MIXED

独立した random ではなく mode bag を使います。

| | CHECKOUT | SETUP | RECOVERY |
| --- | ---: | ---: | ---: |
| 10 問 | 4 | 3 | 3 |
| 30 問 | 10 | 10 | 10 |

### 無限モード

10 問ずつ生成し、**前の chunk の末尾 5 問を次の chunk の直近履歴へ渡します**。
chunk 境界で anti-repeat をリセットしません。

## 9. 160 について

160 は良い残りのひとつです。しかし
**TRAINING は「160 を作るゲーム」ではありません。**

TRAINING の結果表示では、まず

- 次のラウンドで上がれるか
- Bogey か
- 170 超えか

を出します。Premium な残り（170 / 167 / 164 / 161 / 160）は二次情報です。

### 監査での 160 露出

`npm run audit:training` は、推奨解答が作る残りの分布を必ず出します。
**30% を超えても hard failure にはせず、WARNING として原因を分析します。**
「30% を超えた」という理由だけで 160 の問題を人工的に除外してはいけません。

v1.3 時点の測定値（各モード 10 万問）:

```
SETUP  : 160 = 33.9%   MIXED : 160 = 33.3%
```

原因の分析:

- 候補 pool 全体で推奨が 160 になるのは 24.3%。
- カテゴリ別では A（`setup-bogey-avoid`）が 75.0%、C（`setup-digits-0147`）が 63.4%。
- この 2 つは quota が大きい（30 問で 6 + 3 = 9 枠 = 30%）ため、
  セッション全体では約 32% が期待値になる。実測 33.9% はほぼこの期待値どおりで、
  **sampler が 160 を余計に引いているわけではない**。
- 根本の理由は承認済みの戦術方針にあります。`docs/APPROVALS.md` A-7 のとおり、
  160 は BULL を必要とせず D20 で終われるため、170（T20 → T20 → BULL）より上位に
  評価されます。`rankingRules.ts` / `PREMIUM_TENPAI_LEAVES` は
  **Human Approval Required** なので、TRAINING の都合で変更していません。

したがって v1.3 では sampler を調整せず、WARNING と本分析を残しています。
分布を変えたい場合は、カテゴリ quota（本設計 §4）か
承認済みの重み（`docs/APPROVALS.md`）のどちらを見直すかを、人間が決めてください。

## 10. 統計監査

10 万問規模の監査は通常の unit test に埋め込まず、専用スクリプトへ分離しています。

```bash
npm run audit:training              # 各モード 10 万問
npm run audit:training -- --per-mode 3000   # 手元で早く回す
```

hard acceptance（満たさなければ exit 1）:

- 直前とまったく同じ問題: 0
- 直近 5 問以内の同じ `problemKey`: 0
- 同じ問題の最大連続: 1
- MIXED の同じ種別の最大連続: 2
- RECOVERY の解なし: 0 / grader 不一致: 0
- NaN: 0 / undefined: 0
- 復習対象が 1 件だけでも、直前と同じ問題 0・3 連続 0
- **`setup-full` の新規出題: 0**（v1.3.4）
- **1 投調整のうち `decisionRequired` でないもの: 0**（v1.3.4）

SETUP の 160 割合は hard failure ではなく WARNING + 分析です。

report には次も出ます（v1.3.4）。

- `SETUP adjustment / first-dart` … 形式の内訳（80% / 20%）
- `SETUP adjustment decisionRequired` … 調整判断が要る問題の割合（100% が目標）
- `firstDartShortfall` … 候補不足で `setup-adjustment` へ戻した件数
- `SETUP カテゴリ 1 枠ずれ` … 候補の少ないカテゴリと anti-repeat の両立で
  1 枠だけカテゴリを外したセッション数（v1.3.5・仕様どおりで失敗ではない。
  2 枠以上ずれたら hard failure）
