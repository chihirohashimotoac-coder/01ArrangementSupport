# ARRANGE_RULES.md — 評価ルールと重み

> **HUMAN APPROVAL REQUIRED**
> このドキュメントが説明する重み・分類の変更は「戦術方針の変更」に当たります。
> AI が「こちらの方が合理的だから」という理由で書き換えてはいけません。
>
> **現在の値の位置づけ（2026-08-31）**: `GRADE_THRESHOLDS` は
> **v1 暫定値として人間が承認済み**です（`docs/APPROVALS.md` A-8）。
> ここに並ぶ重みは「数学的・統計的に絶対正しい値」ではなく、
> 実戦感覚をもとに人間が選び、運用しながら見直す前提の**戦術方針**です。
> 相対的な大小関係だけに意味があります。

実装は `src/data/rankingRules.ts`（重み）と `src/engine/ranking/checkoutRanking.ts`（特徴の抽出）に
分かれています。**どの特徴を見るか**は engine、**その特徴をどれだけ重視するか**は data の責務です。

---

## 1. 基本方針

数学的に成立するルートを同格に扱いません。ただし、根拠なく重みを決めて「最適」と断定もしません。
評価は加点方式で、合計値の**相対的な大小**にだけ意味があります。

スコアは 2 つ持ちます。

- `score` … 並び順に使う総合スコア（基準ルート加点を含む）
- `tacticalScore` … 基準ルート加点を除いた戦術スコア。**採点（S/A/B/C）はこちらで行う**

「基準ルートだから良い」ではなく「戦術的にどうか」で採点するためです。
基準ルートは定義上つねに S ランクになります。

## 2. 理由コード（CHECKOUT）

| コード | 極性 | 重み | 意味 |
| --- | --- | ---: | --- |
| `STANDARD_ROUTE` | + | 120 | 基準ルートと一致する |
| `FINISH_IN_ONE` | + | 40 | 1 本で上がれる |
| `FEWER_DARTS` | + | 30 | 残り本数より少ない本数で上がれる |
| `SINGLE_MISS_SAFE` | + | 45 | 1 投目をシングルへ外しても上がりが残る |
| `SAFE_SINGLE_START` | + | 45 | 1 投目がシングル狙いで、上下へズレても上がりが残る |
| `SINGLE_MISS_LOSES_CHECKOUT` | − | −50 | 1 投目をシングルへ外すと上がれなくなる |
| `SINGLE_MISS_LEAVES_BOGEY` | − | −25 | 外すと Bogey が残る |
| `NEIGHBOR_SAFE` | + | 18 | 隣ナンバーへ横ズレしても上がりが残る |
| `NEIGHBOR_RISK` | − | −18 | 横ズレすると上がりを失う |
| `GOOD_DOUBLE` | + | 22 | 扱いやすいダブルで終わる |
| `WEAK_DOUBLE` | − | −20 | 扱いにくいダブル（奇数ダブル）で終わる |
| `USER_DOUBLE_PREFERENCE` | + | 動的 | MY ROUTE の得意ダブル（順位に応じて 70〜8） |
| `BULL_REQUIRED` | − | −14 | BULL を要求する |
| `TARGET_CONTINUITY` | + | 12 | 同じナンバーを続けて狙える |
| `EXTRA_TARGET_SWITCH` | − | −6 ×(切替−1) | 狙いの切り替えが多い |
| `SAFER_START_EXISTS` | − | −22 | 同じ本数で、外しても上がりが残る開始が他にある |
| `UNNECESSARY_TRIPLE` | − | −16 | 同じ本数で、トリプルもBULLも使わずに上がれる |
| `NON_FINAL_DOUBLE` | − | −38 ×本数 | 上がり以外でダブルリングを狙っている |

構造的なペナルティ:

- `DART_COUNT_PENALTY = 24` … ダート 1 本あたり
- `TRIPLE_COUNT_PENALTY = 12` … トリプル 1 本あたり（盤面で最も狭い的）

### 補足: 「シングル狙い」を加点する理由

トリプル狙いには「シングルへ落ちる」リスクがありますが、シングル狙いにはそれがありません。
代わりに上下のリング（トリプル / ダブル）へ抜ける可能性があるため、
**その 2 つとも上がりが残る場合にだけ** `SAFE_SINGLE_START` を付けます。
仮定ではなく、engine が実際に計算して判定します。

### 補足: 繋ぎでダブルを狙わない理由

ダブルリングは細く、刻みの的としては割に合いません。
実戦では大きなシングル面か、得点効率の高いトリプルを繋ぎに使います。
`NON_FINAL_DOUBLE` はこの実戦感覚をルール化したものです。

## 3. ダブルの扱いやすさ

`DOUBLE_QUALITY`（`src/data/rankingRules.ts`）で 4 段階に分類します。

- **excellent**: D20 / D16
- **good**: D8 / D4 / D10 / D12 / D18
- **fair**: D2 / D6 / D14 / D1 / BULL
- **awkward**: 奇数ダブル（D3, D5, D7, D9, D11, D13, D15, D17, D19）

基本方針:

- 偶数ダブルは、外してシングルへ落ちても残りが偶数のまま次のダブルへ繋がる
- D16 は 16 → 8 → 4 → 2 と 2 分割が続くため、外したあとの立て直しが最も楽
- 奇数ダブルは、シングルへ落ちると残りが奇数になり組み立て直しが要る

`GOOD_DOUBLE` は excellent / good、`WEAK_DOUBLE` は awkward に付きます。

## 4. 盤面の隣接（`src/data/boardAdjacency.ts`）

`BOARD_NUMBERS`（20 を 12 時方向として時計回り）から機械的に導出します。
目視で表を書き写しません。

例: 20 の隣は 5 / 1、6 の隣は 13 / 10、7 の隣は 19 / 16。

ズレは 2 方向を扱います。

- **横ズレ（horizontal）**: 隣のウェッジの同じリング（T20 → T5 / T1）
- **縦ズレ（vertical）**: 同じウェッジの別リング（T20 → S20、S6 → T6 / D6）

安全性の判定は「ズレた先の残り点が、残り本数でチェックアウト可能か」で行います。

例（46 で S6 を狙う）: 隣の S10 へ横ズレしても `46 − 10 = 36 → D18` が成立するため、
`NEIGHBOR_SAFE` が付きます。

---

## 5. 採点（S / A / B / C）

`GRADE_THRESHOLDS`: S = 差 0、A = 差 25 以内、B = 差 60 以内、それ以外 C。
差は `tacticalScore` の最高値との差です。
この境界値は **v1 暫定値として承認済み**（`docs/APPROVALS.md` A-8）。

さらに **`DISCOURAGING_REASON_CODES`** のいずれかが付いたルートは、
同じ欠点を持たない選択肢が存在する場合、スコア差にかかわらず **C** とします。

```
SINGLE_MISS_LOSES_CHECKOUT / SINGLE_MISS_LEAVES_BOGEY / NEIGHBOR_RISK
SAFER_START_EXISTS / UNNECESSARY_TRIPLE / NON_FINAL_DOUBLE
```

これにより「C には必ず非推奨理由が表示される」ことが構造的に保証されます。

ランクの意味:

- **S** 基準推奨・非常に良い
- **A** 非常に良い代替
- **B** 十分実用的
- **C** 数学的には成立するが戦術的に非推奨（**正解ではある**）

---

## 6. MY ROUTE

STANDARD とは完全に分離します。

- **STANDARD**: 一般的な基準ルート。ユーザー設定で並びが変わらない。
- **MY ROUTE**: `preferredDoubles`（順位つき、BULL も指定可）を加点し、
  基準ルート加点（`applyStandardBonus: false`）を外して並べ替えたもの。

得意ダブルは**加点であって上書きではありません**。戦術的に大きく劣るルートが
得意ダブルというだけで最上位に来ることはありません。

---

## 7. ルートの順序

同じ 3 セグメントでも、`T20 → S3 → D20` と `S3 → T20 → D20` は**別ルート**として評価します。
ルートのキーは順序を含むため、TRAINING の採点でも順番まで判定されます。

v1.3.4 では、この「順序」を決める軸を 2 つ足しました。

- SETUP: 第一ターゲットのシングル落ち耐性（`docs/SETUP_THEORY.md` §10 / APPROVALS A-11）
- NEXT VISIT: 主目標始動（§8）

どちらも**重みではなく明示的な比較**として実装しています。
順序が変わっても、取得点と次ラウンドへの残しは変わりません。

---

## 8. NEXT VISIT の順序（v1.3.5）

CHECKOUT 中に上がれなくなったとき、`selectNextVisitRoute()` は候補を次の順で比べます
（`src/engine/recovery/nextVisitSelection.ts`）。

| 順 | 基準 | 意味 |
| ---: | --- | --- |
| 1 | NEXT VISIT Tier | 残しが次ラウンド何本で上がれるか |
| 2 | いま投げるルートの難易度 | 得意ダブルのために余計なトリプルを要求しない |
| 3 | **主目標始動** | 同じ結果なら、実戦で最初に狙う的（既定 T20）から入る |
| 4 | **第 1 希望の得意ダブル** | その 1 つだけが残しの質より優先される |
| 5 | 残しの質 | 既存の `evaluateLeave()` |
| 6 | **半分にし続けられる回数** | 32 → 16 → 8 → 4 → 2 と続く残しを上に置く |
| 7 | 第 2 希望以下の得意ダブル | 残しの質が完全に並んだときの同点処理 |
| 8 | 取得点が多い（= 残しが小さい） | ここまで同じなら点を取る |
| 9 | 的の切替 / 順番の good practice / キー | 最終 tie-break |

3 と 6 が v1.3.4 の追加、4 と 7 の切り分けが v1.3.5 の修正です
（`docs/APPROVALS.md` A-9 / A-10 / A-14）。

### なぜ 3 が要るか

125 / 2 本では、取得 93 点・32 残し・トリプル 2 本のルートが 10 通りあります。
そこまで同じだと最後に**表記の辞書順**が効き、`T11 → T20` が上位になっていました。
さらに、取得点ごとの代表シーケンス表が上位 8 件で枝刈りされるため、
**`T20 → T11` はそもそも候補から落ちていました**。
主目標始動だけを枝刈りなしで持つ表を足し、比較軸も入れて解決しています。

### なぜ 6 が要るか

130 / 2 本では 16（D8）・28（D14）・40（D20）の 3 つが作れます。
16 は 16 → 8 → 4 → 2 と半分が続くので、次ラウンドでダブルを 1 本外しても
また偶数のダブルが残ります。これは新しい思想ではなく、
承認済みの基準ルート R2（奇数は 32 → 16 → 8 → 4 → 2 の順に立て直しやすいダブルを作る）
と同じ考え方です。

その結果、残り 1 本の NEXT VISIT が基準ルートと同じ形になりました。

```
19 → S3 → 16（D8）
35 → S3 → 32（D16）
```

### なぜ 4 と 7 を分けるか（v1.3.5）

得意ダブルの設定は、以前はアプリの既定で **D16 → D20 → D8 → D10 → D18 の 5 件が
選択済み**でした。順位付きリスト全体を残しの質より上に置くと、
ユーザーが何も設定していないのに「第 2 希望の D20（40 残し）が
第 3 希望の D8（16 残し）に勝つ」という戦術判断が既定値から生まれます。

v1.3.5 では **既定を「未設定（空）」**にしたうえで、5 件を選んでいるユーザーでも
同じ結論になるよう、優先されるのは第 1 希望だけにしました。

```
135 → S5 で 130 / 2 本
  before  T20 → T10（40 残し・D20 は第 2 希望）
  after   T20 → T18（16 残し・16 → 8 → 4 → 2 と半分が続く）
```

第 1 希望だけを残しの質より優先し、第 2 希望以下は同点処理へ下げます。
第 1 希望を D20 にしているユーザーの結果は変わりません（103 / 2 本は `T20 → S3`）。

この切り分けで変わるのは 28 状態で、すべて「40 → 16」「36 → 24」と
半分がより深く続く残しへ動きます。

### 提案は最大 3 件（v1.3.6）

実戦入力（RECOVERY）で上がれなくなったときは、盤面直下に
**投げたあと何点残るか**をつけて、選び方の違う案を最大 3 件並べます
（`selectNextVisitProposals()`）。

| 順 | 種類 | 選び方 |
| ---: | --- | --- |
| 1 | `leave-quality` | 上の比較順そのまま（既定の案内） |
| 2 | `preferred-double` | 得意ダブルの**順位**を残しの質より上に置いた場合 |
| 3 | `alternative` | 的を切り替えずに作れる案（同じ Tier・難易度は上げない） |

```
130 / 2 本（得意ダブルを D16 → D20 → D8 … と設定している場合）
  T20 → T18   16 LEFT   残しの質（D8）
  T20 → T10   40 LEFT   得意ダブル D20
  T19 → T19   16 LEFT   同じナンバーを続ける
```

- 同じルートは重複させません。2 と 1 が同じなら 2 は出しません
  （得意ダブル未設定のときも 2 は出ません）。
- 3 は「同じナンバーを続けて投げられる」案だけ。無ければ出しません
  （D17 → T17 のように、別案のために難しくするのは禁止）。
- 1 件目は `selectNextVisitRoute()` が返す第 1 候補と常に同じです。

### 残り 1 本では 3 を効かせない

「どの順で狙うか」の話なので、投げる本数が 2 本以上のときだけ効かせます。
残り 1 本は順番ではなく「どこへ振るか」の問題なので、残しの質で決めます。
