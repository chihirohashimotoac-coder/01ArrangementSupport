# SPEC.md — 01 Arrangement Support 仕様

## 1. 目的

スティールダーツ 01（Double Out）のアレンジについて、
**答えを表示するのではなく「判断規則」を身につけられる**ことを目的とする。

ユーザーが理解できるようにすること:

- なぜそのナンバーを狙うのか
- なぜ別ルートより安全なのか
- シングルへ外した場合どうなるのか
- 隣接ナンバーへ外した場合どうなるのか
- 次ラウンドへ何点を残すべきなのか

## 2. 設計上の制約

- **生成 AI を runtime の判断に使わない。** 判断は決定論的・再現可能・テスト可能・
  オフライン動作可能な rule based engine で行う。
- ログインなし / バックエンドなし / 外部 DB なし / OpenAI API なし / Claude API なし。
- アプリ本体は完全にオフラインで動作する。
- 秘密情報を必要としない構成（公開リポジトリ前提）。

## 3. ルール

- スティールダーツ、**Double Out**。
- 合法セグメント: `S1〜S20` / `D1〜D20` / `T1〜T20` / `S-BULL = 25` / `BULL = 50` / `MISS = 0`。
- 最終ダートは **Double または BULL**。**BULL = 50 は Double 25 として合法な finish** とし、
  人工的に禁止しない。ただし基準ルートは Excel のデータを尊重する。
- アウターブル（25）では上がれない。

### Bust

次をすべて Bust として扱い、ビジット開始時の残りへ戻す。

- 残りが 0 未満になる
- 残りが 1 になる
- 残りが 0 になったが、最終ダートが Double / BULL ではない

## 3-1. 残り点（LEFT）の入力

実戦中の操作を減らすため、確定操作を挟まない。

- CHECKOUT / SETUP を開いた直後は **空欄（未入力）** から始まる。
  入力するまで候補を計算・表示せず、既定値のルートは出さない。
- **確定ボタン（「セット」）は置かない。** 有効な整数（CHECKOUT は 2〜170、
  SETUP は 171〜350）になった時点で、そのまま候補を再計算する。
- 空欄はエラーにしない。空欄へ戻したら候補を消して未入力状態へ戻る。
- 範囲外では候補を計算しない。入力途中の一時的な無効値ではエラーを出さず、
  入力欄を離れた（blur した）時点でだけ範囲を示す。
- 入力欄に focus すると現在値を全選択し、次の数字でそのまま置き換えられる。
- CHECKOUT と SETUP は別々の状態を持つ。モードを切り替えたら残り点を持ち越さず、
  空欄から始める。
- **よく使う値のプリセットボタンは置かない**（v1.2 で廃止）。
  実戦で必要なのは任意の残り点なので、10 個のボタンが縦を占有するだけになっていた。
  未入力時は `例 103` / `例 302` の placeholder で入力例を示す。
- **入力途中では画面を動かさない。** 103 を打つ途中の `10` もそれ自体は合法な
  CHECKOUT 値なので、有効値になっただけで自動スクロールしてはいけない。
  画面移動は **Enter / Done、または値を書き換えたあとの blur** でだけ行い、
  移動先は StatusBar ではなく答えである STANDARD / BEST の先頭にする。
  iOS では keyboard が閉じてビューポートが確定するのを待ってから動かす。
  3 桁入力になっただけで自動 blur することはしない。

## 4. モード

トップ画面に **CHECKOUT / SETUP / TRAINING** の 3 モードを置く（加えて「設定」）。

### 4-1. CHECKOUT（残り 2〜170）

- **STANDARD**: 基準ルート（`docs/CHECKOUT_DATA_POLICY.md`）
- **MY ROUTE**: ユーザーの得意ダブル（順位つき、BULL 可）を反映した並び。
  STANDARD の並びは変えない。
- **WHY THIS ROUTE?**: 理由コードから組み立てた説明（`docs/ARRANGE_RULES.md`）
- **OTHER ROUTES**: 初期表示は上位 5 件。「すべて表示」を押すと、STANDARD / MY ROUTE として
  別枠に出したものを除いた**合法な候補をすべて**出す（件数の表示と実際の表示件数は必ず一致させる）。
  CHECKOUT では合法な候補が 1400 件を超えることがあるため、
  一度に描画すると重い場合に備えて「さらに 40 件表示」の段階表示も併せて置く。
  段階表示を使っても「すべて表示」で全件へ到達できることを必須とする。

登録済みルートだけを表示するのではなく、残り点と残り本数から
**数学的に成立する Double Out ルートを探索**する。

### 4-2. SETUP（残り 171〜350）

次ラウンドに良い 3 ダートチェックアウトを残す組み立てを提案する。
考え方は `docs/SETUP_THEORY.md`。

- Bogey Number を避ける
- 「とりあえず TON」の罠を警告する
- S-BULL を正式な調整手段として扱う
- テンパイを作れない残りでは、その事実を伝える

### 4-3. RECOVERY（CHECKOUT / SETUP の両方に内蔵）

1 投ごとに実際の着弾を SVG ダーツボードから入力できる。
入力するたびに残り点・残り本数を更新し、候補を再計算する。MISS も入力できる。
Bust したときは、ビジット開始時の残りへ戻ることが分かる UI にする。

### 4-4. TRAINING

- CHECKOUT TRAINING / SETUP TRAINING / RECOVERY TRAINING / MIXED TRAINING
- 回答は SVG ダーツボードのタップ。タップは「そこへ刺さった」ではなく**「そこを狙う」**の意味。
- **自動確定しない。**「回答する」ボタンで確定する。Undo あり。
- 採点は S / A / B / C。数学的に成立するルートを単純に不正解にしない。
  C は「正解ではあるが非推奨」とし、**非推奨理由を必ず表示する**。
- 同じ 3 セグメントでも**順番が違えば別ルート**として判定する。

#### 出題設定

スコア帯 / MIN・MAX 自由指定 / 完全ランダム / 無限練習 / 10 問 / 30 問 / 時間制限あり。
スマートフォンで煩雑にならないよう、詳細設定は折りたたむ。

#### 学習履歴（端末内）

正答率 / 回答時間 / 平均回答時間 / スコア別成績 / スコア帯別成績 / 上がりダブル別成績 /
route rank / 非推奨 route 選択回数 / 苦手スコア / 間違えた問題 / 要復習 / 連続正解 / 学習履歴。

間違えた問題・苦手問題を重点的に再出題できる。
初期版はログイン・クラウド同期・JSON Export/Import なし。ただし将来足しやすい構造にしてある。

## 5. アーキテクチャ

```
UI (components / pages / hooks)
        ↓ 参照のみ
Engine (checkout / setup / recovery / ranking / training)
        ↓ 参照のみ
Data (基準ルート / Bogey / 隣接 / 重み / 説明文 / 資料フィクスチャ)
        ↓ 参照のみ
Domain (盤面 / 得点 / ダート / Double Out ルール)

Storage (localStorage) は UI からのみ使う
```

戦術データを React コンポーネントへ直書きしない。
評価理由は reason code として構造化し、表示用の日本語は `src/data/explanations.ts` で解決する。

## 6. 性能

- チェックアウトの探索は (残り点, 本数) 単位でキャッシュ。全ルート列挙でも数ミリ秒。
- SETUP は取得点ごとの代表シーケンス表を 1 度だけ構築し、以降は取得点 0〜180 の走査だけ。
  アプリ起動後、`requestIdleCallback` で表を温めておく。
- 正しさを優先し、複雑な最適化は必要になってから入れる。

## 7. アクセシビリティ

- SVG の全区画に `aria-label`（例: 「トリプル20、60点」）
- キーボード操作（Tab で移動、Enter / Space で選択）
- タップ領域は 44px 以上（`min-height: 2.75rem`）
- `:focus-visible` のフォーカスリング
- `prefers-reduced-motion` に対応

## 8. 公開

GitHub Pages。`VITE_BASE_PATH` をリポジトリ名から自動決定する。
SPA フォールバックとして `dist/404.html` を生成する。
