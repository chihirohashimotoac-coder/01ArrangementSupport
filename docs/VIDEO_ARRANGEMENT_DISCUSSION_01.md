## 1. 動画の中心理論

> 予定どおりの得点だけでなく、最も起きやすい着弾（特に同ナンバーのシングル）後も、
> 残り本数でチェックアウトまたはテンパイへ復帰できるターゲットを選び、
> 実着弾のたびに次手を再計算する。

この考え方は、すでに次の形で実装済みです。

| 動画の論点 | 現行実装 |
| --- | --- |
| 同ナンバーシングル落ち後もテンパイへ戻れる的を選ぶ（SETUP） | `isSingleMissTenpaiSafe()` と `rankSetupRoutes()` の 4 段ふるい（A-11 / A-18） |
| 同ナンバーシングル落ち後も上がれる的を選ぶ（CHECKOUT） | 理由コード `SINGLE_MISS_SAFE` / `SINGLE_MISS_LOSES_CHECKOUT` / `SAFER_START_EXISTS` |
| 実着弾のたびに次手を計算し直す | `visit.ts` / `useVisit.ts` → `suggestFor()` の再実行 |
| 上がれなくなったら次ラウンドへの残しを作る | `selectNextVisitProposals()`（A-14 / A-17） |
| 得意ダブルで 3 投目の整え方が変わる | `preferences.preferredDoubles` → NEXT VISIT の第 1 希望（A-14） |

そのため、この照合をもとにした**ランタイムの変更はしていません**。
追加したのは Golden / Regression test と、この記録だけです。

## 2. FACT / STRATEGY / PREFERENCE の切り分け

動画の発言を、検証可能性で 3 つに分けます。この区別を曖昧にすると、
「動画で言っていたから正しい」という理由で承認済みの戦術方針を書き換えることになります。

### 2-2. STRATEGY（戦術的な価値判断 / 計算では一意に決まらない）

- 「トリプルが少ないルートの方が成功率が高い」とは限らない。
  S-BULL は狙いが小さく、通常のシングルへ外れると多くの場合テンパイを失う。
  一方 T20 系は同じ的を続けられ、271 では 91 という強い残しになる。
  確率モデルを持たない現行アプリでは、どちらが上とは決められません。
- 「T20 が BULL より常に優れる」も FACT ではありません。
  T20 の隣接 T5 / T1 へ外れるとそれぞれ 106 / 118 になり、2 本では上がれません。
- 233 で seven-count（T19 × 2 + S19 = 133）へ乗り換えるかどうかも STRATEGY です。

### 2-3. PREFERENCE（個人の好み / 実装対象にしない）

- BULL 始動を好むか、盤面の下側へ移りたくないか、1〜3 投の「三角形」を作りたいか。
- D18 派か D12 派か（これだけは既存の得意ダブル設定で表現できます）。
- 1 投目の刺さった位置が 2 投目を物理的に邪魔するかどうか。
  現在の入力は S19 / T19 という区画だけで、座標や遮蔽は保持していません。
  判定には新しい入力が必要なので、TIPS 相当の話として扱います。

## 5. 61 / 2 本の主表示について（変更していません）

動画は 61 / 2 本で `T11 → D14` を推します。S11 へ落ちても 50 が残り BULL で上がれるからです。
現行の基準ルートは `T15 → D8` で、S15 へ落ちると 46 / 1 本になり上がれません。

engine 自身もこの弱点を認識しています。

- `T15 → D8` … `SINGLE_MISS_LOSES_CHECKOUT` + `SAFER_START_EXISTS`
- `T11 → D14` … `SINGLE_MISS_SAFE`、`tacticalScore` は `T15 → D8` より高い

それでも `T15 → D8` が主表示のままなのは、**41〜170 の基準ルートを添付 Excel の
第1候補で固定し、STANDARD を常に別枠で表示する**という現行仕様のためです
（`docs/CHECKOUT_DATA_POLICY.md` §1、`AGENTS.md` §2-2）。

したがって次のとおり扱います。

- 61 だけを書き換える例外（`if (remaining === 61) …`）は**作りません**。
- 基準ルートデータにも `getStandardRoute()` にも手を入れません。
- 「ビジット途中では基準ルートより同ナンバーシングル耐性を優先する」という
  一般ルールへ変えたい場合は、**別 RFC・別 PR・人間の承認**が必要です。
  STANDARD と推奨（RECOVERY）の役割を分離する設計になるため、
  CHECKOUT 2〜170 × 1〜3 本の全 507 状態の差分と、
  TRAINING RECOVERY / SIMULATION レビューの一致確認が前提になります。

この照合の時点では、ユーザーは動画と同じ攻め方を
**OTHER ROUTE として選べば追従できます**（`T11 → D14` は 61 / 2 本の最上位 OTHER）。
その挙動を §3 の test で固定しました。
