# SETUP_THEORY.md — 171〜350 の考え方

## 1. なぜ 350 が上限か

```
1 ビジット最大 180（T20 × 3）+ 3 ダートチェックアウト最大 170（T20 + T20 + BULL）= 350
```

350 は「今のビジットで最大得点を取れば、次ラウンドで上がりうる」境界です。
実装では `MAX_SETUP_REMAINING = MAX_VISIT_SCORE + MAX_CHECKOUT` として、
この式そのものをコードに書いています。

## 2. SETUP の目的

**最大得点を取るゲームではありません。** 目的は「次ラウンドに良い 3 ダートチェックアウトを残す」ことです。

単純に 170 以下なら良い、とは扱いません。3 本以内で合法的に Double Out できるかを判定します。

### Bogey Number（ノーテン）

```
159 / 162 / 163 / 165 / 166 / 168 / 169
```

`src/data/bogeyNumbers.ts` に人間が合意した定義として置き、
`domain/checkoutRules.ts` の動的計画法で計算した結果と一致することをユニットテストで常に検証しています。
片方だけが壊れることを防ぐためです。

## 3. 0・1・4・7

添付資料の「覚えるべき数字」。**159〜170 の帯**では、下一桁が 0 / 1 / 4 / 7 のときだけ 3 本で上がれます。

```
160 ○  161 ○  164 ○  167 ○  170 ○
159 ×  162 ×  163 ×  165 ×  166 ×  168 ×  169 ×
```

**これはこの帯に限った経験則です。** 一般化できません（例: 152 も 158 も 3 本で上がれます）。
実装では `hasMemorableLastDigit()` が帯の内側でだけ true を返し、
`LEAVE_LAST_DIGIT_0147` の加点も +6 と小さく、教材としての印に留めています。
実際の判定は engine の計算（`isCheckoutable`）が行います。

### 340 点台と 180 後の残り

| 得点 | 180 後の残り | テンパイ |
| --- | --- | --- |
| 340 | 160 | ○ |
| 341 | 161 | ○ |
| 342 | 162 | × |
| 343 | 163 | × |
| 344 | 164 | ○ |
| 345 | 165 | × |
| 346 | 166 | × |
| 347 | 167 | ○ |
| 348 | 168 | × |
| 349 | 169 | × |

340 点台で 180 後にテンパイになるのは **340 / 341 / 344 / 347** だけ。全件テスト済みです。

### 【engine が見つけた事実】1 ビジットでテンパイを作れない残り

資料には無い性質ですが、探索から機械的に導かれます。

```
339 / 342 / 343 / 345 / 346 / 348 / 349
```

これは **Bogey Number + 180** とちょうど一致します。この残りからは、
そのビジットで何を取ってもテンパイにできません。
`canReachTenpai()` で判定し、UI では「この残りからはテンパイを作れません」と伝えます。

## 4. 「とりあえず TON」を避ける

100 点を削った結果 Bogey になる残り点があります。

| 残り点 | TON 後の残り |
| --- | --- |
| 269 | 169 |
| 268 | 168 |
| 266 | 166 |
| 265 | 165 |
| 263 | 163 |
| 262 | 162 |
| 259 | 159 |

計算で求めた TON トラップの全件が、この 7 件と一致することをテストしています。

**100 点ではなく 95〜105 点前後へ着地をずらす**という発想が要ります。

```
265 = 19×5 = 95   → 170 残し   （T19 + S19 + S19）
266 = 19×4+20 = 96 → 170 残し   （T19 + S19 + S20）
269 = 19+20×4 = 99 → 170 残し   （S19 + T20 + S20）
```

UI では、TON トラップに当たる残り点で自動的に警告を出します。

## 5. 3 投目で整える（302〜309）

T20 が 2 本入った後（残り − 120）、3 投目をどこへ振るかで次ラウンドが決まります。

| 残り | 3 投目 | 残り |
| --- | --- | --- |
| 302 | 18 | 164 |
| 303 | 19 | 164 |
| 304 | 20 | 164 |
| 305 | 18 | 167 |
| 306 | 19 | 167 |
| 307 | 20 | 167 |
| 308 | 18 | 170 |
| 309 | 19 | 170 |

302 で 3 投目を 20 にすると **162 が残ってノーテン**になります。だから 18 へ振ります。

- シングルに落ちてもテンパイを残せる選択
- 最大得点より、次ラウンドで上がりやすい数字を優先する

engine はこの 8 件すべてで、資料と同じ答えを最上位に出します
（残り 1 本での 3 投目選択、3 本フルの組み立て、どちらでも）。

## 6. S-BULL（25 点）で整える

S-BULL は SETUP の正式な調整手段です。トリプルを使わなくても着地を整えられます。

**231〜235**

```
231 = 20 + 19 + S-BULL = 64 → 167 残し
232 = 20 + 20 + S-BULL = 65 → 167 残し
233 = 19 + 19 + S-BULL = 63 → 170 残し
234 = 20 + 19 + S-BULL = 64 → 170 残し
235 = 20 + 20 + S-BULL = 65 → 170 残し
```

**271〜275**（1 本目に 60 が入った後、18・19・20・S-BULL で 170 へ乗せる）

```
271 = T19 + S19 + S-BULL = 101 → 170 残し
272 = T19 + S20 + S-BULL = 102 → 170 残し
273 = T20 + S18 + S-BULL = 103 → 170 残し
274 = T20 + S19 + S-BULL = 104 → 170 残し
275 = T20 + S20 + S-BULL = 105 → 170 残し
```

10 件すべて、合計・残り・テンパイ成立を検算済みです。
※ engine のランキングがこれらを最上位に置くとは限りません。理由は `docs/DATA_CONFLICTS.md` の #2 を参照。

## 7. 残り点の評価（単純な数値順にしない）

```
170 > 167 > 164 > 161 > 160
```

のような数値順にはしません。次の観点を合成します（`src/engine/setup/leaveQuality.ts`）。

| コード | 重み | 意味 |
| --- | ---: | --- |
| `LEAVES_CHECKOUTABLE` | 100 | 3 本で上がれる（テンパイ） |
| `LEAVES_BOGEY` | −140 | ノーテン |
| `LEAVE_ABOVE_CHECKOUT_RANGE` | −60 | 170 超え |
| `LEAVES_PREMIUM_TENPAI` | 30 | 教材として重要な残り（170/167/164/161/160） |
| `LEAVES_TWO_DART_CHECKOUT` | 26 | 2 本でも上がれる |
| `LEAVE_LAST_DIGIT_0147` | 6 | 0・1・4・7（帯の内側のみ） |
| `LEAVE_REQUIRES_BULL` | −8 | 基準ルートが BULL を要求する |
| `LEAVE_GOOD_FINISH_DOUBLE` | 10 | 扱いやすいダブルで終われる |

重要な残り（`PREMIUM_TENPAI_LEAVES`）には**順位を持たせていません**。
「教材として重要である」という同一の印だけを付け、実際の順位は複数の評価軸の合計で決まります。

その結果、たとえば **160 は 170 より高く評価されます**（BULL を要求せず D20 で終われるため）。
これは意図した挙動で、テストで固定しています。

## 8. 狙う的の難しさ

確率モデルは使いません（初期版では PDC 実績統計等を使わない方針）。
代わりに、盤面上の面積と実戦感覚から人間が決めた**順序データ**を使います。

| 的 | 難易度 | 理由 |
| --- | ---: | --- |
| シングル | 0 | 盤面で最も広い |
| トリプル | 2 | 狭いが、得点効率のために狙う価値がある |
| アウターブル | 3 | ダブルリング同様に細い輪 |
| ダブル | 3 | さらに細く、刻みの的としては割に合わない |
| インナーブル | 4 | 盤面で最小 |

`SETUP_DIFFICULTY_WEIGHT = 12` を掛けて減点します。
取得点は `SETUP_POINTS_WEIGHT = 0.7` で加点します（残りの質より十分小さい）。

この 2 つの重みにより、
「同じ質の残りを作れるなら点を多く取る」「同じ点なら易しい的で取る」という順序になります。

## 9. 探索のしくみ

SETUP のスコアは次のように分解できます。

```
残りの質(leave) + 取得点 × 係数 + シーケンス固有の評価
```

前 2 項は取得点が決まれば一意なので、**取得点ごとに「シーケンス固有の評価が高い上位 8 件」**を
1 度だけ表にしておけば（`src/engine/setup/sequences.ts`）、探索時は取得点 0〜180 を見るだけで済みます。

62³ ≒ 24 万通りの総当たりを毎回行わずに済み、171〜350 の全件探索が表の構築込みで 1 秒未満、
1 件あたり 1ms 未満で終わります。
